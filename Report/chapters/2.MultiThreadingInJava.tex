Nel presente Capitolo verranno discusse le modalità di Programmazione che fanno uso di più Processi Leggeri nel Linguaggio Java.

\section{La Classe ``\texttt{Thread}'' e l'Interfaccia ``\texttt{Runnable}''}
Il Linguaggio di Programmazione Java mette a disposizione nella sua Libreria standard la classe ``\texttt{Thread}''\cite{Thread_JavaDocs}, la quale permette ad uno sviluppatore di scrivere Programmi che diano luce a Processi non Sequenziali. Per raggiungere tale obiettivo essa va ad implementare l'Interfaccia ``\texttt{Runnable}''\cite{Runnable_JavaDocs}, la quale richiede la definizione del metodo ``\texttt{run()}''. \par
\input{images/JavaThreadInheritance.tex}
Ogni oggetto di tipo \textit{Thread} dispone di diversi Metodi e Attributi atti alla gestione del suo Flusso di Esecuzione e alla Sincronizzazione con altri Processi.

\section{Stesura di un semplice Programma Multiprocesso}
L'implementazione di un Programma che risulti nella generazione di più Processi interagenti può avvenire in due distinte modalità, le quali vengono di seguito illustrate.
\subsection{Dichiarazione della Classe come Sotto-Classe di \texttt{Thread}}
Un primo approccio alla Programmazione non Sequenziale può essere quello di estendere la classe cui si vuole donare la possibilità di essere eseguita in un Processo Leggero separato con la Classe \texttt{Thread}. Si riporta a seguire un esempio didattico per l'utilizzo dove il \textit{Thread} principale andrà a creare un numero prestabilito di Processi Leggeri che dovranno stampare sullo Standard Output un messaggio per poi terminare l'esecuzione.
\begin{lstlisting}[language=Java, numbers=left, stepnumber=1]
 /*
 * File: ClassExtendThread.java
 * La classe mira a stampare sullo Standard Output l'identificativo del Thread assegnatogli dal Main. Estende la classe Thread.
 */

public class ClassExtendThread extends Thread {
    
    private int threadNumber;

    public ClassExtendThread(int tNum) {
        this.threadNumber = tNum;
    }

    @Override
    public void run() {
        System.out.println("Sono il Thread numero " + this.threadNumber + ".");
    }
}   
\end{lstlisting}
La classe dovrà sovrascrivere l'Implementazione di default del metodo ``\texttt{run()}'' fornita dalla classe \texttt{Thread}, inserendo il codice da eseguire all'avvio dell'esecuzione del Processo Leggero associato.
\begin{lstlisting}[language=Java, numbers=left, stepnumber=1]
 /*
 * File: MainExtendThread.java
 * La classe crea un numero NUM_OF_THREADS di Thread che estendano la classe Thread.
 */

public class MainExtendThread {

    private static final int NUM_OF_THREADS = 5;

    public static void main(String[] args) {

        System.out.println("Sono il Main e sto per creare i Thread.");        
        
        for(int i=0; i<NUM_OF_THREADS; i++) {
            ClassExtendThread cet = new ClassExtendThread(i);
            cet.start();
        }

        System.out.println("Sono il Main ed ho terminato l'esecuzione.");
    }
}
\end{lstlisting}
La creazione di un oggetto di tipo ``\texttt{ClassExtendThread}'' munisce il Programmatore del metodo ``\texttt{start()}'' fornito dalla Classe \texttt{Thread} per eseguire il codice della Classe in un Processo Leggero separato.
\subsection{Implementazione dell'Interfaccia \texttt{Runnable}}
La controparte richiede un'implementazione molto simile, di seguito vengono riportate le differenze.
\begin{lstlisting}[language=Java, numbers=left, stepnumber=1]
 /*
 * File: ClassImplementRunnable.java
 * La classe mira a stampare sullo Standard Output l'identificativo del Thread assegnatogli dal Main. Implementa l'interfaccia Runnable.
 */

public class ClassImplementRunnable implements Runnable {
    ...
}
\end{lstlisting}
La Classe che prima andava ad estendere \texttt{Thread} ora deve implementare l'interfaccia \texttt{Runnable}, ma al di fuori di questo non sono necessarie modifiche nella sua struttura.
\begin{lstlisting}[language=Java, numbers=left, stepnumber=1]
 /*
 * File: MainExtendThread.java
 * La classe crea un numero NUM_OF_THREADS di Thread che estendano la classe Thread.
 */
...
for(int i=0; i<NUM_OF_THREADS; i++) {
    ClassImplementRunnable cir = new ClassImplementRunnable(i);
    Thread thread = new Thread(cir);
    thread.start();
}
...
\end{lstlisting}
La vera differenza risulta nell'utilizzo della Classe appena descritta: bisognerà infatti crearne un'istanza da passare al Costruttore di \texttt{Thread} in maniera tale da generare un oggetto di di quest'ultima tipologia che implementi il metodo ``\texttt{run()}'' desiderato. Si potrà poi procedere con una metodologia di utilizzo pari alla precedente. \par
Notando che Java non permette di estendere più di una Classe alla volta, ma mantiene la possibilità di implementare più Interfacce contemporaneamente, si preferisce generalmente questo ultimo approccio nonostante necessiti di una implementazione più verbosa. \par
In ogni caso l'output del Programma sopracitato può assumere diverse forme a causa della mancanza di alcuna forma di sincronizzazione tra i vari Processi, una delle quali è di seguito raffigurata.
\begin{lstlisting}[language=Bash]
[tcosimi@VivoBook-Arch]:~$ java MainImplementRunnable
Sono il Main e sto per creare i Thread.
Sono il Main ed ho terminato l'esecuzione.
Sono il Thread numero 2.
Sono il Thread numero 3.
Sono il Thread numero 0.
Sono il Thread numero 4.
Sono il Thread numero 1.
\end{lstlisting}
Si noti come l'esecuzione del \textit{Thread} principale termini prima di quella degli altri Processi Leggeri da lui generati ma che questa circostanza non limiti in alcun modo questi ultimi, che continueranno la loro esecuzione fino alla terminazione.

\section[Controllo del Flusso di Esecuzione]{Metodi per il controllo del Flusso di Esecuzione}
La classe \texttt{Thread} mette a disposizione alcuni metodi per la gestione del Flusso di Esecuzione dei singoli Processi Leggeri\cite{SeminarioJavaDispense}. Ciò risulta utile nel caso in cui si voglia controllare il loro ordine di esecuzione o ancora la loro possibilità di eseguire. \par
\subsection*{Il metodo \texttt{start()}}
Il metodo ``\texttt{start()}'' permette di inzializzare l'esecuzione del Processo Leggero tramite l'invocazione del metodo ``\texttt{run()}'' poc'anzi citato.
\subsection*{Il metodo \texttt{stop()}}
Il metodo ``\texttt{stop()}'' permette di interrompere invece l'esecuzione del Processo Leggero attraverso l'utilizzo dell'eccezione ``\texttt{ThreadDeath}''.
\subsection*{Il metodo \texttt{suspend()}}
Il metodo ``\texttt{suspend()}'' permette di sospendere momentaneamente l'esecuzione di un \textit{Thread} fin tanto che su di lui non venga chiamato il metodo \texttt{resume()}, portandolo dallo stato ``\textit{Running}'' allo stato ``\textit{Blocked}''.
\subsection*{Il metodo \texttt{resume()}}
Il metodo ``\texttt{resume()}'' permette di riprendere l'esecuzione di un \textit{Thread} bloccato dal metodo \texttt{suspend()}, portandolo dallo stato ``\textit{Blocked}'' allo stato ``\textit{Ready}''.
\subsection*{Il metodo \texttt{sleep(int millis)}}
Il metodo ``\texttt{sleep()}'' permette di portare il Processo Leggero nello stato ``\textit{Blocked}'' (o ``\textit{Sleeping}'' se si fa riferimento a sistemi *NIX-Like) per un determinato numero di millisecondi passato come argomento senza utilizzare cicli di Clock della CPU. Tale metodo solleva un'eccezione di tipo ``\texttt{InterruptedException}'' nel caso in cui tale Processo Leggero venisse interrotto da un altro Processo mentre è già in stato ``\textit{Sleeping}'', perciò il metodo viene incapsulato in un costrutto di tipo ``\textit{Try-Catch}''.
\subsection*{Il metodo \texttt{yield()}}
Il metodo ``\texttt{yield()}'' permette al \textit{Thread} di lasciare volontariamente la CPU ad un altro processo, implicando un \textit{Re-Scheduling}.
\subsection*{Il metodo \texttt{join()}}
Il metodo ``\texttt{join()}'' consente al Processo Padre di attendere la terminazione del Processo Figlio prima di continuare con la propria esecuzione, garantendo un semplice meccanismo di sincronizzazione tra i due.

\subsection{Problemi del Controllo del Flusso di Esecuzione}
Così come discusso nel \autoref{Chap:Introduzione} l'arbitraria interruzione dell'esecuzione di un Processo potrebbe portare a situazioni indesiderate: una o più risorse potrebbero risultare in uno stato non consistente, oppure ancora una risorsa che era stata acquisita dal \textit{Thread} che ha subito l'interruzione avrebbe la possibilità rimanere bloccata, portando sotto le giuste ipotesi in uno stato di \textit{Deadlock}. Per questi motivi si preferisce non utilizzare in maniera imperativa i Metodi ``\texttt{stop()}'', ``\texttt{suspend()}'' o ``\texttt{resume()}''. \par
\subsection{Soluzioni e Considerazioni sul Controllo del Flusso di Esecuzione}
Alle primitive sopracitate si preferisce usufruire della possibilità di segnalare ai Processi la possibilità di sospendersi o terminare la loro esecuzione, in maniera tale da permettere loro di eseguire le proprie Sezioni Critiche e lasciare il Sistema in uno stato consistente. Un esempio di Metodo che permette al Processo Leggero di lasciare volontariamente la CPU è ``\texttt{yield()}''. La natura delle moderne versioni della \textit{Java Virtual Machine} implica poi l'utilizzo dello \textit{Scheduler} del Sistema Operativo, il quale dovrà scegliere il prossimo Processo cui lasciare il controllo. Notando che tutti i moderni Algoritmi di \textit{Scheduling} supportano l'utilizzo di un valore di Priorità per la scelta del Processo da inserire nella Coda ``\textit{Ready}'', anche Java mette a disposizione un valore di Priorità per i propri Processi Leggeri: esso varia tra il valore minimo ``\texttt{MIN\textunderscore PRIORITY}'' (0) ed il valore massimo ``\texttt{MAX\textunderscore PRIORITY}'' (10) e viene impostato in maniera automatica - al netto di ulteriori istruzioni - su ``\texttt{NORM\textunderscore PRIORITY}'' (5), risultando visualizzabile e personalizzabile rispettivamente tramite le Primitive ``\texttt{getPriority()}'' e ``\texttt{setPriority()}''.
